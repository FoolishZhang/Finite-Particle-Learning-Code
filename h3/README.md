# Proposal structure, local shrinkage, and saved risk evidence

These materials accompany **Importance Proposals Can Reverse Model Rankings and
Induce Local Correlation Shrinkage**, the scientific core used by the h3.2/h3.2.1
research manuscript. They are a named public code-and-evidence release, not an
anonymous submission or a claim of acceptance.

The package contains the actual observed data for the 96 fixed-condition
validation datasets, saved fitted coordinates and risks, all start-specific
diagnostics, saved per-replicate proposal comparisons, original scientific
implementations, proof sources, and the source and inputs of all three figures.
It adds no new experiment or new inference. The older h2.2 release and its data
assets remain separately available and unchanged.

## Run the supported checks

Use Python 3.11 in a fresh environment and install h3/requirements.txt (or the
repository's existing requirements). From the repository root:

    python -I -m pip --isolated install -r h3/requirements.txt
    python -I -B h3/tools/check.py --mode all --output ../h3-check-001.json
    python -I -B h3/tools/plot.py --output-dir ../h3-figures-001
    python -I -B h3/code/local_risk/local_shrinkage_risk_algebra_test.py --output-dir ../h3-algebra-001

Every output must be new; use paths outside this checkout. Do not use -O or
-OO. The first command installs dependencies. The check verifies file hashes,
imports scientific modules in isolated namespaces, validates observed data,
and independently reconstructs the original saved-value summaries and
intervals. It does **not** sample particles, compute model integrals, fit a
model, establish statistical coverage, or certify exact empirical minimizers.
The algebra command uses fixed rational polynomial identities, not new data.

The plotting command calls the original plotting functions. It reads saved
means, standard errors and confidence endpoints and evaluates the existing
local-risk formula on a display grid. Font/library differences can change PNG
bytes on another platform; the command reports comparison with archived
images rather than altering them.

The complete within-group channel is known. There are three standard-normal
active variables with unknown physical correlations. Each has a logistic binary
observation and M binary private observations with independent Gaussian private
variables, private scale tau and active connection epsilon. Marginalizing a
private variable gives h_tau(s)=E sigmoid(tau G+s). A group is represented by
its binary label and count of positive private responses; its conditional
probability includes the binomial multiplicity. Risk is the KL of all three
groups' complete joint law. The algebra and source files use these same
coordinates and channel, not a learned encoder or unknown nuisance model.

## Data roles and numerical qualifications

- [Observation index](data/OBSERVATION_INDEX.json) identifies all 96 datasets
  (153,600 observed rows). Each CSV preserves original row order and six integer
  columns: count_1, count_2, count_3, Y_1, Y_2, Y_3. These are observed responses
  only, not the teacher's unobserved latent draws.
- [Scientific configuration](data/local_risk/SCIENTIFIC_CONFIG.json) preserves
  the four fixed teachers, N, K=8, channel, original starts, solver and numerical
  budgets. It is a public scientific projection, not the original runner's
  management contract.
- The 96 cases are **not** 96 randomly drawn teachers. The four conditions have
  24 independent datasets each. N=256 and N=2048 use different teachers and
  independent data, not nested samples from one teacher.
- For fitted methods, CASE_METHOD_RISKS.csv averages the two original **risks**,
  not the two fitted coordinates; additional rows retain untrained references. FIT_OUTPUTS.json preserves all six fit outputs per case.
  PRIMARY_CASE_VALUES.csv has 96 comparison rows, but only 72 distinct datasets
  in the four primary comparisons because the two middle-signal comparisons
  share data. No extra independence is implied.
- All 864 saved risk-order comparisons passed. Group stationarity diagnostics
  passed on 48/48, 44/48, 12/48 and 6/48 outputs in the four conditions; ML and
  ridge jointly passed 384/384. Failures remain in the published data and
  analysis. Passing stationarity is not a global-optimum certificate.
- J1 compares two proposals within each fixed M. Earlier KL values in
  data/j1/OLD_RISK_SCALE.json are scale references from a different risk
  evaluation, not new risk samples for J1. Gamma was chosen after an exploratory
  Gaussian study and fixed before subsequent validation/paired comparisons.
  The selection rule was not preregistered before that development study.
- The local theoretical region is shared by group posterior and matched ridge
  relative to ML and independence. It is not universal optimality, a measured
  finite-N crossing, or an equivalence test for the programs.

## Reproduction levels

|Level|Included and supported here|
|---|---|
|File identity and saved arithmetic|Complete for the explicitly listed public inputs, four J1 intervals, four local-risk intervals, plot points, diagnostic counts and observation serialization.|
|Observed validation data and output inspection|All 96 observed datasets, original scientific settings and all 576 fitted coordinates are available without downloading a large release asset.|
|Scientific source inspection/import|Original modules and their local dependencies are copied byte-for-byte into separate namespaces. New public callers are separately identified in [SOURCE_MAP](SOURCE_MAP.json).|
|Full original scientific replay|**Not provided as a supported command and not rerun.** Full particle banks, complete saved PMF laws, all traces and private one-run management records are not bundled. Original top-level runners deliberately retain historical identity checks; do not disable them or pretend the public projection is their original contract.|

Exact observation values and fitted coordinates make further independent
evaluation possible with the published kernels, but that is new computation.
A passing inexpensive check does not reproduce original particle scores,
quadrature or optimization. [CODE_STATUS](CODE_STATUS.json) records this
distinction explicitly. No large h3 data asset is required for supported
commands, and no existing data-v1.0.0 asset is replaced.
