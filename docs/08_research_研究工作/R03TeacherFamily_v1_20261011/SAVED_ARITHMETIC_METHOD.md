# R03 独立保存算术审计

实现为 `script/r03_saved_arithmetic_audit.py`，只使用 Python 标准库 Fraction、整数 `isqrt`、JSON 与哈希。它不导入 flint、NumPy、研究积分核或任何生产合成模块，也不通过重新调用 producer.compute 冒充独立实现。收据为 `artifacts/r03_teacher_family_v1_20261011/SAVED_ARITHMETIC_AUDIT.json`。

## 算术边界

保存区间的 dyadic 端点被精确读为有理数。加、减、乘、除均按独立区间公式计算，并向外舍入到绝对步长 `2^-256` 的 dyadic 网格，以避免非 dyadic 分母在 LDL 和 256 项风险求和中指数增长。舍入使用整数商的 floor/ceil；平方根通过整数 `isqrt` 给出上下端，并用 Fraction 验证平方夹逼。区间跨零的乘积按四个端点乘积取界，不使用一般实幂。

这种保存算术实现不要求与 Arb 的每一步区间形状相同。关键检查是重建包围落在原保存包围中、独立严格不等式通过，以及原/新证据状态不发生矛盾。新的证明失败不等于对象反例；旧未通过的谱主元仍作为失败记录保留。

## h001 的逐层独立重建

1. 核对 BOX_FREEZE 的全部字节绑定、SPECTRAL_REFINEMENT 的输入与源码绑定，并重建原连续合成器所记录的 compactinputs、16 个候选分块、teacher、risk 四个对象的规范 JSON 哈希。读取期间任何已绑定文件改变都拒绝交付。
2. 从教师完整有限和与保存的解析 L1 误差帽重建 256 项真实 q0、256 项真实 q′0 的误差转移，核对原真值区间确实包围；检查质量恒等式相容性和保存的二阶导数帽。解析零质量来自已绑定模型证明，数值包含零不被当成证明。
3. 从完整 128 个已完成互补标签条件行和原 256 教师权重，独立折叠正负 q′，重建 8 维 G1，以及三块 H0、H1、Hlambda 的全部 576 项。核对配置、标签、外层节点覆盖及所有保存合成包围，不采用旧 41 类压缩。
4. 从精确 A、原中心、半径、旧梯度/根距帽、原条件解析误差和保存的固定中心，独立重建教师零质量余项上界、八个 Y/Z、包含余量及加权收缩率。A 正定性用独立 Fraction 区间 LDL 检查。h001 的每个严格自映射和收缩门都必须通过，旧中心梯度没有设为零。
5. 从原风险 `Q_finite/N_finite` 和各自保存解析误差帽重建全部 256 项真实 Q/N，独立正分母除法得到 rho。随后分别重建原 R0、own-target 中心化 R0、二者交集、带符号 R1 和零质量 Taylor 尾，并严格检查风险曲率上端小于零。own-target 恒等式 `sum N=0` 仍以已绑定解析证明为前提，没有以数值求和接近零替代它。

## 原/新谱检查与其它盒

对谱收据提供的每一个已完成盒，直接从其原三块 8×8 `Hlambda_finite` 端点重建精确中点、64 项半宽平方和及 rho 上端的 Fraction 平方验证。重新计算固定精确 a0 的 Householder 表达式，核对投影中点包围，用独立 LDL 验证新 `.1/.02/.005` 门限，核对未降低目标、总 shift 及 core 状态。

同时在原保存 Hbb/Haa 或原已投影横向区间矩阵上重做原门限 LDL，并保留原记录的通过/失败。已记录为通过的原门必须仍能独立证明；原记录未决时，独立算术仍只报告自身结果，不改写原失败。原根或风险未通过的盒不能因谱改进获得完整结论。最终收束区间必须仍为 `[-1/1000,1/1000]`。

其它盒的覆盖限于上述谱保存算术、哈希、原根/风险状态及旧失败保留；没有重新逐标签合成其它盒的 Y/Z 或风险。h001 是唯一完整执行 128 标签根包含与 256 标签风险重建的盒。这一区别在收据中明确保存。

## 没有重新证明或执行的内容

本审计不重跑任何 Gaussian/Laplace 积分节点、内层因子、优化或随机程序，不读取 NPZ；不重新推导或评估 alias/tail/global-cap 解析表达式。原条件有限和区间正确性、解析余项证明、教师零质量及补标签恒等式、Ward 关系、精确 Householder 正交性和旧根证书都属于已绑定数学输入。保存算术核验不能被表述为重新独立取得并认证全部底层原始积分。

十项制造夹具覆盖有符号区间乘法、正分母除法、独立平方根平方夹逼、定向舍入、LDL 成功与失败、非零 own-target 两式恒等、严格门与非严格门区分、精确八文件 raw 白名单，以及第九项或科学证书绑定不得豁免。

## 本地模式与 public-only 模式

默认 `reconstruct()` 或普通 CLI 实际读取并流式哈希 `DEV_RAW_INDEX.json` 中的八个本地开发 raw 文件，同时核对其字节数。这八个文件严格限定为 `DEVELOPMENT.json` 和 `DEV_POINT_000.json` 至 `DEV_POINT_006.json`；列表缺项、增加其它路径、SHA256 格式错误或字节数无效均被拒绝。

`reconstruct(public_only=True)` 与 `--public-only` 只对这八个文件允许使用公开 `DEV_RAW_INDEX.json` 的历史 SHA256/bytes 记录。当原冻结清单引用某个 raw 哈希时，仍须与索引值完全一致；公开 DEVELOPMENT_PUBLIC 的 `source_raw` 哈希和字节数、投影源码绑定也必须与索引一致。该模式不打开 raw 内容，也不声称重新独立哈希了缺失的 raw 文件。公开索引、公开投影和所有其它已绑定源文件仍实际读取并哈希，严格条件积分、教师、风险、谱证书等科学输入没有豁免。

两种模式的全部算术、严格门、规范返回对象和 canonical 收据相同。CLI 在收据之外单独报告 `verification_mode`，避免把文件可用性方式写成不同的科学结论。收据保存八项历史 raw SHA256/bytes 及索引/公开投影自身字节绑定，`--check --public-only` 因而可在没有约 800 MB 本地 raw 内容的公开环境中复核同一严格保存算术结果。

```powershell
python -B script/r03_saved_arithmetic_audit.py --self-test
python -B script/r03_saved_arithmetic_audit.py --write
python -B script/r03_saved_arithmetic_audit.py --check
python -B script/r03_saved_arithmetic_audit.py --check --public-only
```

`--write` 在完整实际保存算术审计成功后写出新收据，拒绝覆盖已有文件。`--check` 只读重建并要求与保存收据完全一致；两者均不修改冻结源码、原目标结果或旧证书。本轮为加入公开模式而在授权范围内更新衍生审计收据的来源绑定，未改冻结科学输入；本地与公开模式已作同值比较。
