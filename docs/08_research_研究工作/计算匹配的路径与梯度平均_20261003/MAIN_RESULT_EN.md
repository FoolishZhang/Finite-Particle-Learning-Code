# Lower observation risk can receive a worse particle score at matched sampling budgets

We compare two prespecified finite-step procedures on four fixed datasets, with 16 fresh independent prior quartets per dataset. IN4 averages four K100 gradients at one state before one Adam/repair step. OUT4 runs four independent single-bank paths and averages their physical TAIL parameters, where TAIL averages the final 64 post-update states. Each strategy uses the same four prior inputs and concept-loss calls; OUT4 uses four times as many optimizer/repair calls.

Mean observation joint KL is 0.0058173972 for IN4 and 0.0026813001 for OUT4. The OUT4-minus-IN4 difference is −0.0031360971, with the original q3 training-family development t interval [−0.0044855750, −0.0017866193]. Independent evaluation of the realized outputs instead gives higher raw particle scores for OUT4 under both empirical D weights (+0.0018194682) and numerical population P weights (+0.0016976662); both original q2 evaluation intervals are positive. Each family uses alpha=0.025. Training inference conditions on the four datasets; evaluation inference additionally conditions on the realized output panel.

The conditional parameter-dispersion and squared conditional-mean-error estimates both decrease, but their original simultaneous intervals include zero. All five precision thresholds pass; only one of three training directions and both evaluation directions are resolved. These are development t approximations, not exact coverage certificates.

The untrained identity matrix has a previously qualified reference KL of 0.0027110543, close to the OUT4 mean. This post-hoc descriptive comparison adds no test or interval and does not establish superiority over identity or equivalence. Thus the result supports a controlled risk-versus-objective ranking separation, not a practical correlation-recovery guarantee. Parameter averaging is not a new algorithm here; OUT4 is not a predictive mixture, and parameter variance identities do not imply KL dominance.

The experiment includes 320 low-dimensional optimization programs, zero new observations and zero neural-network fits. Each strategy uses 131,072 training API calls; optimizer/repair calls are 32,768 versus 131,072, so total cost and wall time are not asserted equal. Production runs completed once.
